## Why a probe was needed

The migration's own verification block reports structure: seven values in the check
constraint, two tables, two unique constraints, one `security definer` function. A
unique constraint that exists is not a replay that was refused, and a role test that
compiles is not a manager who was turned away. Both probes run inside transactions that
end in `rollback`, so nothing they write is committed.

Impersonation is `set local role authenticated` plus `set local request.jwt.claims`,
which is what makes `auth.uid()` inside `pto_decide()` answer as a specific signed-in
user. Fixture dates are in 2099 and 2100, so no real schedule, closed date, or balance
year is involved.

### The concurrent case

`v1.9.3-pto-decide-lock-race.sql` run twice in parallel, both against the same committed
pending request, ~700 ms apart:

| Run | `lock_wait_ms` | applied | movement | verdict |
| --- | --- | --- | --- | --- |
| first | 18 | true | 7.0 | one movement, exactly the deltas |
| second | 2384 | true | 7.0 | one movement, exactly the deltas |

The second run waited 2.4 seconds. That is the `select ... for update` on the request
holding it outside the first run's decision rather than letting it validate against
state that was mid-change. It then applied its own movement in full. This is the
behaviour Appendix A.5's read-then-write pair cannot produce: there, both callers read
the same figure and the second write discards the first increment.

Both runs rolled back, so neither movement was committed.

No loss anywhere. The two gains are live application traffic, not migration or probe
writes, and each was identified rather than assumed:

- **`audit_log` +4** — all four rows are Quotes activity (`quote_deleted` on a duplicate,

  `attendance_audit_log`. This is the same reading the stage-3 run recorded.
- **`time_clock_breaks` +1** — an open lunch break started at 18:46:59 with a null
  `break_end`: an employee is on lunch. Neither the migration nor either probe references
  the table.

Nothing the probes wrote survived: `pto_request_decisions`, `pto_balance_ledger`, and
`attendance_audit_log` are all empty, no request holds one of the three new statuses, no
2099 or 2100 fixture remains, and the `_probe_decide` helper the probe created inside its
transaction is gone.
